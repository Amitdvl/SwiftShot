/goal Finish SwiftShot as a dependable, pleasant daily screenshot tool and ship the existing product. Prioritize the user's experience and Codex usage over exhaustive certification. This replaces the earlier requirement to complete every six-milestone benchmark and environment matrix before shipping.

Start with the orchestration skill. One lead owns scope, integration, final review and verification. Reuse existing evidence; use a bounded reviewer when useful, not parallel work for its own sake. I authorize multiple tasks/subagents subject to runtime limits, with isolated writes and one accountable lead. Only the lead operates shared app/UI/install tests. Disclose unavailable delegation.

Product priorities, in order:
1. Trust: capture the intended region/window/display; preserve native pixels; Copy produces a pasteable image; Save writes the correct image; redactions are opaque and exports contain no embedded original. Keep recovery, private mode and warnings about editable originals trustworthy. Fix reproducible data loss, privacy failures, crashes or wrong output before shipping.
2. Experience: make capture -> select -> annotate -> Copy/Save feel quick and predictable. Check focus restoration, precise selection, basic annotation editing, shortcuts and sensible raw defaults. Fix obvious friction or regressions, not speculative micro-optimizations or cosmetic redesigns.
3. Preserve the features already built: history reuse, pins, presets, combining, Shortcuts and manual/automatic scrolling. Give them proportionate smoke checks. Fix known material failures; retain honest incomplete-scroll warnings. Do not expand features or redesign architecture to satisfy the old checklist.
4. OCR is secondary. Keep on-device recognition accurate enough for ordinary readable text, with a working clipboard result, recoverable errors and no damage to screenshot workflows. First inspect existing code/evidence: bitmap rendering already avoids PNG and warm native runs were about 100-115 ms from OCR admission to clipboard. A single first-use run was about 7.5 s and remains unattributed. Do one bounded reliability/first-use check; fix an obvious reproducible problem if found. Otherwise document the limitation and move on. No OCR benchmark campaign, broad language matrix, new phase-tracing infrastructure or perfection target. Do not call it fully optimized without evidence.

Finish efficiently: identify a short list of actual release blockers from the current diff and evidence; address those only. Run focused tests for changes, then the existing full Release suite once on the final candidate (rerun after fixes only as needed). Perform one representative native smoke pass on available hardware. Review the intended diff, build/package/install safely, verify the installed app, update docs and commit/push only intended SwiftShot changes.

Constraints: preserve user changes and existing safety tests. Keep native Swift/ScreenCaptureKit, local-only behavior and macOS 14 fallbacks. No cloud, video, generative AI, framework rewrite, new test infrastructure for its own sake, or repeated statistical batches. Retain failed evidence; do not hide broken output or weaken privacy/correctness protections. Historical latency targets and unavailable 4K/HDR/multidisplay/OS checks are follow-up evidence, not release blockers by themselves. Mark them unverified, never passed.

Done means the core workflows work, confirmed material blockers are resolved, final tests/review/install smoke pass, and intended changes are committed/pushed. Report product improvements, evidence and residual limits briefly. Keep docs/GOAL_PROGRESS.md current. Stop when this finish line is met; do not reopen the old certification campaign.
